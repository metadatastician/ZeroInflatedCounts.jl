== What this is, and how it works

*What it is.* A dated, signed snapshot of what can honestly be claimed about
*ZeroInflatedCounts.jl* at the single commit named in <<verifiable-anchor>>.
It is a receipt, not a roadmap: plans live in `README.adoc` and in
`docs/method-conditions/zero-inflation-and-hurdle.adoc`.

*What the project is.* A Julia package that fits hurdle negative binomial
(`hurdle_nb`) and zero-inflated negative binomial (`zinb`) models to one count
table, one taxon at a time, by calling R's `pscl` through RCall. A pure-Julia
log-likelihood lives in the test suite only, as an independent oracle. The
fits are meant to be shown beside a plain NB GLM, never instead of it.

*How it stays trustworthy.* Every claim below was produced by running the
command cited next to it, in the session that wrote this file. The anchor
fixes the commit, the time and the toolchain. The owner's signed commit is
the signature.

[#nuance]
=== The honest nuance you must not lose

* *636 is executions, not distinct assertions.* `grep -cE
  "@test(_throws)?\b" test/cases/*.jl` gives 264 source lines carrying a
  test macro (102 at `d987960`); loops in several files run some of them many
  times.
* *The two errors are in a test fixture, not in a model fit.* Both stack
  traces have RCall's `setindex!(::Ptr{EnvSxp}, ::Missing, ::String)` as the
  innermost frame, raising "MethodError: no method matching
  protect(::Int32)", and neither stack passes through the package's own
  source. The failing line,
  `test/cases/36-fit-responses.jl:98`, interpolates each case value into R,
  and the last case's value is Julia `missing`. Measured separately: `using
  RCall; v = missing; R"x <- $v"` exits 1 with the same MethodError on RCall
  0.14.14, and the same line with `v = NaN` exits 0. CI shows the same two
  errors on RCall 0.14.6 (Julia 1.9 job) and 0.14.14 (Julia 1 job), so the
  error is not specific to this machine.
* *What the abort left unrun is read from the source, not measured.* Each of
  the two aborted testsets printed Pass 30, Error 1 of 31. By reading the
  file, the six earlier cases (5 assertions each) completed, including the
  non-finite standard-error cases that exercise the reordered check in
  `src/core/models.jl`. The `missing` standard-error case, the two
  "no fit" message cases and the "controlled bridge error" case did not run
  for either model.
* *The simulation tests are regression alarms, not calibration.* Each
  recovery test runs 10 repeats at 20 samples per group and requires the
  planted value inside the 95% interval in at least 70% of repeats. The file
  says so itself: "a regression alarm for a broken estimator, not a
  calibration certificate." The ZINB dispersion check uses a median over the
  repeats with a bound of [1, 8].
* *The null simulation covers `hurdle_nb` only*, 8 repeats of 6 taxa, and
  "fdr" there is discoveries divided by taxa tested under a global null.
  `zinb` has no null-simulation test at the anchor.
* *The cross-check shares R and `pscl` with the code under test.* It guards
  against a mistake in this package's bridge (wrong sign, dropped offset,
  wrong pair of log-likelihoods), not against a defect in `pscl` itself.
* *Dependencies were resolved fresh.* No `Manifest.toml` is committed, so a
  later `Pkg.instantiate` may resolve different RCall or Aqua versions. CI's
  Julia 1.9 job resolved RCall 0.14.6, not 0.14.14.
* *The Agda check needed a local fix.* The machine's `~/.agda/libraries`
  points at files that no longer exist, so the repo's own
  `bash scripts/check-proofs.sh agda` printed "RESULT: FAIL (1 failure(s),
  0 unexpected pass(es))" for an environment reason, not a proof reason. The
  file was then checked with an explicit library file, as shown in
  <<solid>>.

=== Known-incomplete but honestly fenced

* *Taxa whose fit cannot be computed* are returned as `TaxonRefused` (a
  condition visible in the counts) or `TaxonFailed` (`pscl` reported a
  failure), and neither carries a p-value. This is fenced by
  `test/cases/30-refusals.jl` and `test/cases/60-results.jl`, which
  completed, and by the parts of `test/cases/36-fit-responses.jl` that ran
  before the abort.
* *A machine without R cannot load the package.* `RCall` is a hard
  dependency in `Project.toml`, so the failure is a load error, not a silent
  fallback.
